WL_C#

La transition naturelle de WINDEV vers Visual Studio & C#

WL_C# est une librairie C# destinée en priorité aux développeurs qui connaissent et utilisent couramment le WLangage de WINDEV mais qui peuvent être plus mal à l'aise sur l'environnement Visual Studio ou le langage C#/C++ en général.

Son objectif est simple :
faciliter le passage vers C# et Visual Studio,
sans perdre les habitudes, les automatismes et le confort
apportés par les fonctions du WLangage.

Lorsqu'un développeur WINDEV découvre C#, il retrouve un langage extrêmement puissant, mais également une philosophie différente. De nombreuses opérations très simples en WLangage nécessitent de connaître les bonnes classes .NET, les bonnes méthodes, et parfois plusieurs lignes de code.

WL_C# sert de passerelle entre ces deux environnements.

La librairie reproduit progressivement en C# un ensemble de fonctions familières du WLangage : manipulation des chaînes, fichiers et répertoires, dates, conversions, presse-papiers, fonctions système, etc. Un développeur habitué à écrire une fonction WINDEV peut ainsi retrouver en C# un nom, un comportement et une logique d'utilisation qu'il connaît déjà, tout en travaillant dans l'écosystème C# / .NET.

WL_C# n'a pas vocation à remplacer .NET, ni à masquer C#. Elle permet au contraire à un développeur venant du monde WINDEV :

  • de réduire la courbe d'apprentissage,
  • d'accélérer le développement,
  • de rendre le code immédiatement plus familier.
// Ouverture d'un fichier externe
int IDFichier;
string ResLecture;
IDFichier = fOuvre("C:\MesRépertoires\Fichier.txt", foLectureEcriture)
if (!IDFichier==-1)
{
      // Lecture d'une ligne dans ce fichier
      ResLecture = fLitLigne(IDFichier)
       ...
}

La librairie est développée et validée à l'aide d'une importante suite de tests automatisés (plus de 3600 tests à ce jour), afin de vérifier autant que possible la compatibilité du comportement des fonctions proposées.

Deux environnements finalement très proches

Pour un développeur WINDEV, le passage vers Visual Studio et C# est beaucoup moins dépaysant qu'on pourrait le penser. Les deux environnements présentent de nombreuses similitudes : organisation générale de l'IDE, explorateur de projet, éditeur de code, complétion automatique, débogueur, gestion des projets et des configurations, sans oublier de nombreux raccourcis clavier et réflexes de développement très proches. Un développeur habitué à WINDEV retrouve donc rapidement ses repères dans Visual Studio.

La principale différence ne se situe finalement pas tant dans l'environnement de développement que dans le langage lui-même. Là où le WLangage fournit directement un très grand nombre de fonctions prêtes à l'emploi, C# s'appuie davantage sur les classes et les différentes API de .NET. C'est précisément à cet endroit que WL_C# intervient : permettre au développeur WINDEV de conserver une partie de son vocabulaire et de ses automatismes tout en découvrant progressivement la puissance de C# et de .NET.

Exemples d'utilisation

À gauche, le code que vous écrivez avec WL_C# — le même vocabulaire qu'en WLangage. À droite, ce qu'il faudrait écrire en C# pur, avec les seules classes .NET, pour obtenir exactement le même résultat sans la librairie.

WinDev — et C# avec WL_C#

if (!fFichierExiste(cheminFichier))
{
    fSauveTexte(cheminFichier, sTexte);
}
string sMajuscule = Majuscule(sTexte);
string sRepertoireTemp = fRepTemp();

C# pur, sans WL_C#

if (!File.Exists(cheminFichier))
{
    File.WriteAllText(cheminFichier, sTexte);
}
string sMajuscule = sTexte.ToUpper();
string sRepertoireTemp = Path.GetTempPath();

WinDev — et C# avec WL_C#

string fichier = fSélecteur("", "", "Choisissez un fichier",
    "Fichier texte (*.txt)|*.txt", "*.txt", fselCrée);
if (fichier != "" && !fFichierExiste(fichier))
{
    int idFichier = fCrée(fichier);
    fEcrit(idFichier, "Bonjour depuis WL_C#");
    fFerme(idFichier);
}

C# pur, sans WL_C#

using Microsoft.Win32;

SaveFileDialog sélecteur = new SaveFileDialog();
sélecteur.Filter = "Fichiers texte (*.txt)|*.txt";
if (sélecteur.ShowDialog() == true)
{
    string fichier = sélecteur.FileName;
    if (!File.Exists(fichier))
    {
        using StreamWriter flux = new StreamWriter(fichier);
        flux.Write("Bonjour depuis C#");
    }
}

En pratique

Utiliser WL_C#

  1. Vérifier les prérequis

    WL_C# fonctionne sous Windows 10 version 2004 (build 19041) ou plus récent, avec le runtime .NET 10 Desktop — déjà présent si vous avez installé le SDK .NET 10.

  2. Télécharger la bibliothèque

    Récupérez la dernière archive sur la page des Releases, et décompressez-la dans un dossier lib de votre projet :

    lib/
 ├─ WL.dll
 ├─ Constantes.dll
 ├─ ChronoComp.dll
 ├─ WL.Webservices.dll   (facultative : webservices, voir plus bas)
 ├─ WL.TraceViewer.exe
 └─ Donnees/Pays.ReferenceVersion.json
    Voir la dernière version →

  3. Configurer votre projet

    Dans le .csproj de votre projet, ciblez la même plate-forme que WL_C#, référencez WL.dll et ajoutez les paquets NuGet dont elle a besoin :

    <PropertyGroup>
  <TargetFramework>net10.0-windows10.0.19041.0</TargetFramework>
  <UseWindowsForms>true</UseWindowsForms>
</PropertyGroup>

<ItemGroup>
  <Reference Include="WL">
    <HintPath>lib\WL.dll</HintPath>
  </Reference>
  <PackageReference Include="ClosedXML" Version="0.105.1" />
  <PackageReference Include="DocumentFormat.OpenXml" Version="3.5.1" />
  <PackageReference Include="libphonenumber-csharp" Version="9.0.40" />
  <PackageReference Include="Markdig" Version="1.3.2" />
  <PackageReference Include="Microsoft.Toolkit.Uwp.Notifications" Version="7.1.3" />
  <PackageReference Include="NetTopologySuite" Version="2.6.0" />
  <PackageReference Include="PdfPig" Version="0.1.16" />
  <PackageReference Include="PDFsharp" Version="6.2.4" />
  <PackageReference Include="SharpCompress" Version="0.50.4" />
  <PackageReference Include="SharpZipLib" Version="1.4.2" />
  <PackageReference Include="System.IO.Ports" Version="8.0.0" />
  <None Update="lib\Donnees\Pays.ReferenceVersion.json" Link="Donnees\Pays.ReferenceVersion.json" CopyToOutputDirectory="PreserveNewest" />
  <None Update="lib\WL.TraceViewer.exe" Link="WL.TraceViewer.exe" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>

    Sans ces paquets NuGet, les fonctions Excel, Markdown, géolocalisation, ports série, masques de saisie, notifications, PDF et archives s'arrêtent sur une erreur « fichier introuvable » dès leur premier appel. La plate-forme windows10.0.19041.0 est nécessaire aux fonctions Bluetooth, et UseWindowsForms aux fonctions presse-papiers, polices et boîtes de dialogue. Les deux lignes None copient automatiquement à côté de votre exécutable le dossier Donnees (utilisé par PaysContinents) et WL.TraceViewer.exe (la fenêtre qui affiche les Trace()).

  4. Importer les fonctions dont vous avez besoin

    Chaque catégorie de fonctions est une classe statique. Plutôt que d'ajouter un using static au fil de l'eau dans chacun de vos fichiers, le plus simple est d'ajouter un seul fichier GlobalUsings.cs à votre projet — comme le fait WL_C# en interne — pour rendre toutes les fonctions accessibles sans préfixe, partout dans votre code :

  5. Premier programme

    Une fois GlobalUsings.cs en place, les fonctions s'utilisent directement, sans aucun préfixe :

    string sTexte = Majuscule("bonjour depuis WL_C#");
fSauveTexte(fRepTemp() + "\\essai.txt", sTexte);

  6. Exposer un webservice (facultatif)

    Les fonctions WebserviceParamètre, WebserviceEcritCodeHTTP, WebserviceEnvoieMorceau, DéclareContexteWebservice... sont dans WL.Webservices.dll, à part pour que WL.dll n'impose pas ASP.NET Core aux projets qui n'en ont pas besoin. Pour un webservice REST, ajoutez au .csproj :

    <ItemGroup>
  <FrameworkReference Include="Microsoft.AspNetCore.App" />
  <Reference Include="WL.Webservices">
    <HintPath>lib\WL.Webservices.dll</HintPath>
  </Reference>
</ItemGroup>

    puis, dans GlobalUsings.cs :

    global using Microsoft.AspNetCore.Builder;
global using static WL.Webservices;

    Les points d'entrée se déclarent comme dans la description d'un webservice REST de WEBDEV : méthode HTTP, ressource et procédure.

    var app = WebApplication.Create(args);
app.UtiliseWebservicesWL();
app.PointEntréeWebservice("GET", "/Clients/{NumCli}", ws_LitClient);
app.PointEntréeWebservice("POST", "/Clients", ws_CréeClient, paramètreDésérialisé: "client");
app.Run();

string ws_LitClient(int NumCli)
{
    if (NumCli <= 0) { WebserviceEcritCodeHTTP(404, "Client inconnu"); return ""; }
    WebserviceEcritTypeMIME(typeMimeJSON);
    return "{\"numero\":" + NumCli + "}";
}

    Le serveur est celui d'ASP.NET Core (Kestrel, ou IIS). Les éléments variables de la ressource ({NumCli}) et les paramètres de l'URL remplissent les paramètres de même nom de la procédure ; ce qu'elle renvoie devient la réponse. Côté client, les types wsRequête et wsRéponse de WL.dll appellent un webservice SOAP.

  7. Avec l'IDE de votre choix

    WL_C# est une bibliothèque .NET standard : elle fonctionne avec Visual Studio, JetBrains Rider, Visual Studio Code, ou tout autre IDE prenant en charge .NET 10.
