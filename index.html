WL_C#

La transition naturelle de WINDEV vers Visual Studio & C#

WL_C# est une librairie C# destinée en priorité aux développeurs qui connaissent et utilisent couramment le WLangage de WINDEV. Son objectif est simple : faciliter le passage vers C# et Visual Studio, sans perdre les habitudes, les automatismes et le confort apportés par les fonctions du WLangage.

Lorsqu'un développeur WINDEV découvre C#, il retrouve un langage extrêmement puissant, mais également une philosophie différente. De nombreuses opérations très simples en WLangage nécessitent de connaître les bonnes classes .NET, les bonnes méthodes, et parfois plusieurs lignes de code.

WL_C# sert de passerelle entre ces deux environnements.

La librairie reproduit progressivement en C# un ensemble de fonctions familières du WLangage : manipulation des chaînes, fichiers et répertoires, dates, conversions, presse-papiers, fonctions système, etc. Un développeur habitué à écrire une fonction WINDEV peut ainsi retrouver en C# un nom, un comportement et une logique d'utilisation qu'il connaît déjà, tout en travaillant dans l'écosystème C# / .NET.

WL_C# n'a pas vocation à remplacer .NET, ni à masquer C#. Elle permet au contraire de réduire la courbe d'apprentissage, d'accélérer le développement et de rendre le code immédiatement plus familier pour un développeur venant de WINDEV.

La librairie est développée et validée à l'aide d'une importante suite de tests automatisés (plus de 1900 tests à ce jour), afin de vérifier autant que possible la compatibilité du comportement des fonctions proposées.

Deux environnements finalement très proches

Pour un développeur WINDEV, le passage vers Visual Studio et C# est beaucoup moins dépaysant qu'on pourrait le penser. Les deux environnements présentent de nombreuses similitudes : organisation générale de l'IDE, explorateur de projet, éditeur de code, complétion automatique, débogueur, gestion des projets et des configurations, sans oublier de nombreux raccourcis clavier et réflexes de développement très proches. Un développeur habitué à WINDEV retrouve donc rapidement ses repères dans Visual Studio.

La principale différence ne se situe finalement pas tant dans l'environnement de développement que dans le langage lui-même. Là où le WLangage fournit directement un très grand nombre de fonctions prêtes à l'emploi, C# s'appuie davantage sur les classes et les différentes API de .NET. C'est précisément à cet endroit que WL_C# intervient : permettre au développeur WINDEV de conserver une partie de son vocabulaire et de ses automatismes tout en découvrant progressivement la puissance de C# et de .NET.

En pratique

Utiliser WL_C#

  1. Télécharger la bibliothèque

    Récupérez la dernière archive sur la page des Releases, et décompressez-la :

    WL_v1.0.zip
 ├─ WL.dll
 └─ Donnees/Pays.ReferenceVersion.json
    Voir la dernière version →

  2. Référencer WL.dll

    Dans votre projet, ajoutez une référence au fichier WL.dll (clic droit sur le projet → Ajouter une référence → Parcourir), ou directement dans le .csproj :

    <ItemGroup>
  <Reference Include="WL">
    <HintPath>lib\WL.dll</HintPath>
  </Reference>
</ItemGroup>

    Conservez le dossier Donnees à côté de votre exécutable : certaines fonctions (PaysContinents) en ont besoin au démarrage. WL s'appuie aussi sur WinForms pour certaines fonctions (presse-papiers, polices, boîtes de dialogue...) : pensez à activer <UseWindowsForms>true</UseWindowsForms> dans votre propre projet si vous utilisez ces fonctions.

  3. Importer les fonctions dont vous avez besoin

    Chaque catégorie de fonctions est une classe statique. Plutôt que d'ajouter un using static au fil de l'eau dans chacun de vos fichiers, le plus simple est d'ajouter un seul fichier GlobalUsings.cs à votre projet — exactement comme le fait WL_C# en interne — pour rendre toutes les fonctions accessibles sans préfixe, partout dans votre code :

    global using static WL.Chaines;
global using static WL.Commandes;
global using static WL.Constantes;
global using static WL.Couleurs;
global using static WL.Date;
global using static WL.Dialogues;
global using static WL.DiversUtils;
global using static WL.Fichiers;
global using static WL.Ftp;
global using static WL.Listes;
global using static WL.MarkDown;
global using static WL.Numeriques;
global using static WL.PaysContinents;
global using static WL.Polices;
global using static WL.PortsSérieParallèle;
global using static WL.PressePapiers;
global using static WL.Projet;
global using static WL.Registres;
global using static WL.Souris;
global using static WL.Système;
global using static WL.Tableaux;

    using static WL.Constantes; est particulièrement important : c'est ce qui permet d'utiliser les constantes WLangage (psdJSON, PremierElément, fselCrée...) sans préfixe, exactement comme en WLangage.

  4. Premier programme

    Une fois GlobalUsings.cs en place, les fonctions s'utilisent directement, sans aucun préfixe :

    string sTexte = Majuscule("bonjour depuis WL_C#");
fSauveTexte(fRepTemp() + "\\essai.txt", sTexte);

  5. Avec l'IDE de votre choix

    WL_C# est une bibliothèque .NET standard : elle fonctionne avec Visual Studio, JetBrains Rider, Visual Studio Code, ou tout autre IDE prenant en charge .NET 10.
